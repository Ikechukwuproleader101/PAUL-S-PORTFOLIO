# Hero Entrance Animation Spec (GSAP)

Photography portfolio, hero section. This document explains **what** the entrance should look like and **how** to build it with GSAP.

---

## 0. READ THIS FIRST: Reference Rules (for any AI or developer building this)

There is an **animation components folder** in this project (confirm the exact path before starting, e.g. `/animation-components/`). It is the **source of truth** for how the animations should look and behave.

1. **Open and read the folder before writing any code.** Reuse the components, helpers, easings, and timings that already exist in it.
2. **Do not invent substitutes.** Do not generate fake, "close enough", or look-alike versions of components that exist in the folder. If the folder has a pixel text component, use it. Do not rewrite it from scratch.
3. **Do not guess letter shapes.** The pixel letterforms must come from the design file or the reference folder. The bitmaps in this document are illustrative only.
4. **If something is missing or unclear, stop and ask.** Do not fill the gap with an unreliable guess.
5. If the folder and this document disagree, **the folder wins** for visuals; this document wins for sequencing and structure. Flag the conflict.

## 1. The Design Being Animated

- Solid **red background** filling the hero.
- **Cut-out portrait** (transparent PNG, white outline) of a person in sunglasses, centered, cropped at the bottom.
- Giant **pixel-style "PHOTOGRAPHER"** text across the bottom. White blocks with a black offset "shadow" blocks. The text sits **in front of** the portrait and overlaps the shoulders.
- Top **nav bar** (light grey): "Portfolio" on the left; About, Projects, Contact, Experience on the right.

### Layer order (back to front)

| z-index | Layer |
|---|---|
| 0 | Red background |
| 1 | Portrait (transparent PNG) |
| 2 | Pixel text (shadow blocks, then white blocks) |
| 3 | Nav bar |

The overlap between the portrait and the text is what gives the hero depth. Keep this order exactly.

---

## 2. The Animation Flow

Total length target: **about 3 to 3.5 seconds**. It should feel confident, not rushed.

| Time (approx.) | Step | What happens |
|---|---|---|
| 0.0s | Setup | Hero is hidden until fonts and images are ready |
| 0.0 to 0.8s | 1. Background | Red wipes in (clip-path reveal from the top or bottom) |
| 0.5 to 1.7s | 2. Portrait | Rises up slightly and scales down from 1.08 to 1, fading in, with a soft ease |
| 1.1 to 2.7s | 3. Pixel text | Pixels pop in one by one, randomly scattered across the word. White blocks first, black shadow blocks right after |
| 2.4 to 3.0s | 4. Nav | Slides down from above and fades in |
| 3.0s onward | 5. Idle | Portrait floats gently; subtle mouse parallax |

Use overlapping positions on one timeline (negative offsets or absolute times) so the steps flow into each other instead of running as a strict queue.

## 5. Pixel-by-Pixel Text: The Technique

Each letter is described as a small grid (bitmap). Each filled cell becomes one small block element. GSAP then animates every block with a stagger.

### 5.1 Letter data

```js
// ILLUSTRATIVE ONLY. Real bitmaps must come from the design / reference folder.
const LETTERS = {
  P: [
    "11110",
    "10001",
    "11110",
    "10000",
    "10000",
  ],
  // ...one entry per letter used in "PHOTOGRAPHER"
};
```

### 5.2 Build the blocks

```js
function buildPixelText(container, word, letters) {
  const frag = document.createDocumentFragment();

  [...word].forEach((char) => {
    const grid = letters[char];
    const letter = document.createElement("span");
    letter.className = "px-letter";
    letter.setAttribute("aria-hidden", "true");
    letter.style.setProperty("--cols", grid[0].length);

    grid.forEach((row) => {
      [...row].forEach((cell) => {
        const px = document.createElement("i");
        px.className = cell === "1" ? "px" : "px px--empty";
        letter.appendChild(px);
      });
    });

    frag.appendChild(letter);
  });

  container.appendChild(frag);
}
```

```css
.px-letter { display: grid; grid-template-columns: repeat(var(--cols), 1fr); flex: 1; }
.px        { aspect-ratio: 1; background: #fff; }
.px--empty { background: transparent; }
/* Black offset shadow: a second set of blocks (or a pseudo-element)
   offset by one cell, sitting behind the white blocks. Match the design. */
```

**Important:** keep the `<h1>` readable to screen readers with `aria-label`, and mark the generated blocks `aria-hidden`.

## 6. The Master Timeline

```js
function playEntrance() {
  const tl = gsap.timeline({ defaults: { ease: "power3.out" } });

  // 1. Background wipe
  tl.from(".hero-bg", {
    clipPath: "inset(0% 0% 100% 0%)",
    duration: 0.8,
    ease: "power4.inOut",
  });

  // 2. Portrait rises in
  tl.from(
    ".hero-portrait",
    { yPercent: 12, scale: 1.08, autoAlpha: 0, duration: 1.2 },
    0.5
  );

  // 3. Pixels pop in, scattered randomly
  tl.from(
    ".px:not(.px--empty)",
    {
      scale: 0,
      autoAlpha: 0,
      duration: 0.3,
      ease: "back.out(2)",
      stagger: { amount: 1.2, from: "random" },
    },
    1.1
  );

  // 4. Nav slides down
  tl.from(".nav", { yPercent: -100, autoAlpha: 0, duration: 0.6 }, 2.4);

  // 5. Idle motion starts when the entrance ends
  tl.add(startIdle, 3.0);

  return tl;
}
```

### Tuning notes

- **Pixel feel:** for a harder, more "digital" snap, swap the ease for `"steps(1)"` or shorten the duration to about 0.15s.
- **Alternate order:** replace `from: "random"` with `from: "start"` for a left-to-right build, or `{ grid: "auto", from: "center" }` for a ripple.
- **Shadow blocks:** animate them in the same way, offset by about 0.1 to 0.2s, so the black appears just after the white.

## 7. Portrait Extras

### 7.1 Idle float

```js
function startIdle() {
  gsap.to(".hero-portrait", {
    y: -8,
    duration: 3,
    ease: "sine.inOut",
    yoyo: true,
    repeat: -1,
  });
}
```

### 7.2 Mouse parallax (subtle)

```js
const portrait = document.querySelector(".hero-portrait");
const moveX = gsap.quickTo(portrait, "x", { duration: 0.8, ease: "power3" });
const moveY = gsap.quickTo(portrait, "rotation", { duration: 0.8, ease: "power3" });

window.addEventListener("mousemove", (e) => {
  const nx = e.clientX / window.innerWidth - 0.5;   // -0.5 to 0.5
  moveX(nx * 20);
  moveY(nx * 1.5);
});
```

Keep it small. If a viewer notices the parallax consciously, it's too strong. Disable on touch devices.

## 8. Loading Gate (avoids flash and jank)

Do not start until fonts and the portrait have loaded.

```js
async function init() {
  const img = document.querySelector(".hero-portrait");
  await Promise.all([
    document.fonts.ready,
    img.decode().catch(() => {}),
  ]);

  buildPixelText(document.querySelector(".hero-title"), "PHOTOGRAPHER", LETTERS);
  document.querySelector(".hero").classList.remove("is-loading");
  playEntrance();
}

init();
```

```jsx
    // build pixel blocks in JSX (preferred) or via the helper in section 5,
    // then create the timeline from section 6 here
  }, { scope: root });

  return <section ref={root} className="hero">...</section>;

```

`useGSAP` handles cleanup automatically. Scope selectors to the root ref so animations never touch other components. Prefer rendering the pixel blocks in JSX (mapping over the bitmaps) rather than manual DOM building.

## 10. Accessibility and Performance

**Reduced motion**

```js
const mm = gsap.matchMedia();

mm.add("(prefers-reduced-motion: no-preference)", () => {
  playEntrance();
});

mm.add("(prefers-reduced-motion: reduce)", () => {
  // Show the final state immediately, or use a simple fade only
  gsap.set([".hero-bg", ".hero-portrait", ".px", ".nav"], { clearProps: "all" });
});
```

**Performance**

- Animate only `transform` and `opacity` (GSAP's `x`, `y`, `scale`, `rotation`, `autoAlpha`). Avoid animating `width`, `height`, `top`, or `left`.
- About 300 pixel blocks is fine. If you push far beyond that, consider SVG rects or canvas.
- Use `will-change: transform` only on the portrait, not on every block.
- Compress the portrait PNG (or use WebP/AVIF with transparency).
